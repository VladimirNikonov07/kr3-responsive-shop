# PULSE SPORT LAB

Контрольная работа №3 по дисциплине «Фронтенд и бэкенд разработка». Тема — адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта.

Никонов Владимир Сергеевич, ЭФБО-16-25.

[Открыть магазин](https://vladimirnikonov07.github.io/kr3-responsive-shop/) · [Исходный проект КР №1](https://github.com/VladimirNikonov07/pulse-sport-lab)

Магазин спортивной экипировки включает десять товаров в четырёх категориях. Можно подобрать товар, посмотреть характеристики кроссовок, открыть подсказку по размеру и заполнить заявку. Обе формы учебные и проверяют данные в браузере.

## Структура и запуск

| Файл | Назначение |
| --- | --- |
| index.html | Главная, направления, популярные товары и преимущества |
| catalog.html | Каталог, переходы к разделам и фильтр по категории |
| product.html | Кроссовки, характеристики и диалог подбора размера |
| guide.html | Подбор экипировки по виду активности |
| order.html | Заявка с подстановкой выбранного товара из адресной строки |
| contacts.html | Контакты, частые вопросы и форма обратной связи |
| css/style.css | Оформление компонентов, цвета, шрифты и отступы |
| css/responsive.css | Сетки, медиазапросы, мобильное меню и представление характеристик |
| js/main.js | Меню, фильтр, диалог, заполнение и проверка форм |
| images/ | Фотографии товаров в WebP и резервное изображение |
| lighthouse/ | Три сохранённых HTML-отчёта |

Для запуска откройте `index.html` в браузере. Сборка и установка зависимостей не требуются.

## Что изменилось относительно КР №1

- Сохранены шесть страниц, товары, фотографии и оформление спортивного магазина. На каждой странице после общего CSS подключён `responsive.css`. Тег viewport задаёт ширину устройства и стартовый масштаб 1.
- На телефоне hero, карточка товара, каталог и форма занимают одну колонку. С 420 px направления и подвал переходят в две колонки. С 640 px товары и поля формы располагаются в две колонки.
- С 768 px постоянно видны ссылки шапки, а фото в hero и на странице товара располагается рядом с описанием. С 1024 px фильтр занимает боковую колонку, каталог показывает три карточки в ряду, блок популярных товаров — четыре. Контейнер ограничен шириной 1180 px.
- Меню на телефоне раскрывается кнопкой. Состояние передаётся через `aria-expanded`, Escape закрывает меню и возвращает фокус. Без JavaScript навигация остаётся открытой.
- Фильтр показывает выбранную категорию и сообщает количество видимых товаров через `role="status"`. Ссылки на разделы позволяют перейти к нужной категории и при отключённом JavaScript.
- На странице товара с 640 px показана таблица с заголовками строк и столбцов. На телефоне каждая пара «характеристика — значение» оформлена как карточка через `dl`, `dt`, `dd`. Скрытое представление исключается из дерева доступности с помощью `display: none`.
- Для фотографии кроссовок подготовлены WebP шириной 360 и 750 px. В `srcset` указаны реальные ширины файлов, а `sizes` описывает предполагаемую ширину изображения в макете. Браузер учитывает и плотность экрана.
- На странице контактов появилась отдельная форма. Подписи связаны с полями через `for` и `id`. У полей есть встроенная проверка типа и обязательности.
- Ссылка пропуска ведёт на `main`. Усилен контраст вторичного текста и номеров преимуществ, фокус выделен двухцветным контуром. У изображений есть описания. Нативный `dialog` удерживает клавиатурный фокус, закрывается по Escape и возвращает фокус к вызвавшей его кнопке. При системной настройке уменьшения движения отключаются плавная прокрутка и переходы.

## Контрольные вопросы

1. **Что такое адаптивная вёрстка?** Это вёрстка, в которой размеры и расположение элементов меняются в зависимости от доступного места. Например, фотография товара на телефоне стоит над описанием, на широком экране — рядом.
2. **Что такое Mobile First?** Сначала задают стили узкого экрана. Затем через медиазапросы добавляют колонки и меняют расположение элементов для более широких экранов.
3. **Для чего нужен viewport?** `width=device-width` связывает ширину области вёрстки с шириной устройства в CSS-пикселях. `initial-scale=1` задаёт исходный масштаб.
4. **Для чего нужен responsive.css?** В этом проекте он собирает правила, определяющие поведение страниц на разных ширинах. Так проще найти точку перехода сетки.
5. **Почему его подключают после style.css?** При одинаковой важности, слое и специфичности побеждает более позднее правило. Поэтому в отдельном файле можно изменить базовую сетку компонента.
6. **Что такое медиазапрос?** Это условие применения CSS. Например, `@media (min-width: 640px)` включает правила при ширине окна от 640 CSS-пикселей включительно.
7. **Почему удобно min-width?** При расширении окна ранее включённые правила продолжают действовать. Для следующего размера достаточно описать изменения.
8. **Как адаптировать навигацию?** На телефоне ссылки раскрываются кнопкой «Меню», с 768 px они видны постоянно. Ссылки и кнопка доступны с клавиатуры.
9. **Как адаптировать сетку карточек?** У Grid-контейнера меняют число колонок. В каталоге здесь одна колонка до 640 px, две до 1024 px и три с 1024 px. `minmax(0, 1fr)` позволяет колонкам сжиматься.
10. **Как адаптировать боковой фильтр?** На телефоне разместить его перед списком, на широком экране выделить ему отдельную колонку. Здесь один и тот же фильтр работает в обоих положениях.
11. **Что такое responsive images?** Это изображения, для которых размер вывода или загружаемый файл подстраивается под условия просмотра.
12. **Для чего srcset?** Он перечисляет варианты одного изображения. Например, `360w` сообщает браузеру, что файл имеет ширину 360 пикселей.
13. **Для чего sizes?** Он подсказывает, сколько места займёт изображение при заданной ширине окна. Вместе с плотностью пикселей это помогает выбрать файл из srcset. Реальный размер в макете задаёт CSS.
14. **Для чего picture?** Он позволяет задать несколько источников через `source`, например другой кадр для телефона или другой формат файла. Внутри остаётся `img` с описанием. Для двух разрешений одного кадра в этой работе хватает srcset и sizes.
15. **Как адаптировать форму?** На узком экране ставят поля друг под другом, растягивают по ширине контейнера, оставляют видимые подписи и удобную высоту. Здесь с 640 px короткие поля занимают две колонки, комментарий — всю строку.
16. **Как адаптировать таблицу?** Можно прокручивать только её контейнер. В проекте на телефоне вместо широкой строки показаны подпись и значение друг под другом. С 640 px появляется обычная таблица.
17. **Почему горизонтальный скролл страницы — ошибка?** Часть текста и кнопок оказывается за экраном, приходится двигать всю страницу в двух направлениях. Проверить переполнение можно сравнением scrollWidth и clientWidth у документа.
18. **Что проверяет Lighthouse?** В категории Accessibility он автоматически проверяет, например, контраст, доступные имена кнопок и ссылок, подписи полей и некоторые ошибки семантики.
19. **Почему нужна ручная проверка?** Автоматический тест может обнаружить наличие alt, но не оценить, насколько точно он описывает товар. Удобство порядка Tab, заметность фокуса и понятность результата отправки стоит проверять в самом интерфейсе.
20. **Какие самостоятельные доработки добавлены?** Раскрывающееся меню с Escape, рабочий фильтр со счётчиком, карточки характеристик на телефоне, два разрешения фотографии кроссовок, отдельная форма обратной связи и улучшения контраста и фокуса.
